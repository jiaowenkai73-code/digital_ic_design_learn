# Log 5 - UART TX RTL Design

## What I Learned

Today I learned the basic concepts of UART communication and started implementing a UART transmitter from scratch in Verilog.

The frame format is 8N1: one start bit, eight data bits, no parity bit, and one stop bit. The data is transmitted least significant bit (LSB) first.

```text
Start bit -> DATA[0] -> DATA[1] -> ... -> DATA[7] -> Stop bit
```

The UART line is high when idle. The start bit is low, and the stop bit is high.

## RTL Design

Design file: [uart.v](../03_uart/uart.v). The module name is `uart_tx`.

The transmitter uses four FSM states:

```text
IDLE
  | start_tx
  v
START_BIT
  | one baud period
  v
DATA[0] -> DATA[1] -> ... -> DATA[7]
  | final data bit completes
  v
STOP_BIT
  | one baud period
  v
IDLE
```

### Baud timing

The system clock is 50 MHz, so one clock period is 20 ns. The target baud rate is 115200:

```text
50,000,000 / 115,200 = approximately 434 clock cycles per bit
434 * 20 ns = 8.68 us per bit
```

A 9-bit `baud_counter` controls the duration of each transmitted bit. Counting from 0 through 433 gives 434 clock cycles. The counter resets at the end of each bit period and remains at zero in IDLE.

### Internal registers

```verilog
reg [1:0] current_state;
reg [1:0] next_state;
reg [8:0] baud_counter;
reg [2:0] data_counter;
reg [7:0] data_reg;
```

- `current_state` stores the current FSM state.
- `next_state` is generated by combinational logic and determines the next state.
- `baud_counter` determines when one UART bit period has completed.
- `data_counter` tracks which of the eight data bits is being transmitted.
- `data_reg` captures the input data when a transmission request is accepted, preventing later changes on the external input from affecting the frame.

During the DATA state, the serial output selection is:

```verilog
tx = data_reg[data_counter];
```

This sends `data_reg[0]` through `data_reg[7]` in order.

## Questions and Understanding

This implementation helped me review the difference between combinational and sequential logic.

The state register, counters, and data capture use clocked sequential logic. State transition decisions and the `tx` output use combinational logic.

Several details became clearer:

- `current_state` only updates on a clock edge.
- `next_state` determines where the FSM should go next.
- A register in a clocked block keeps its previous value when no assignment occurs.
- `start_tx` requests a transmission and only needs to be sampled high when the transmitter is idle; it does not need to remain high for the entire frame.
- UART idle and stop levels are high, while the start bit is low.
- UART data is transmitted LSB first in this design.

## Current Implementation Status

The revised `uart.v` contains the completed first RTL implementation. The module declaration and block endings are corrected, and `next_state` defaults to `current_state`.

The input byte is captured into `data_reg` on a rising clock edge when `start_tx` is accepted in IDLE. This clocked block uses nonblocking assignments and resets `data_reg` to zero. The DATA state selects `data_reg[data_counter]`, and `tx` stays high in IDLE until the FSM enters START_BIT.

The revised source passes the following Icarus Verilog compilation check from the repository root:

```sh
iverilog -Wall -tnull -s uart_tx 03_uart/uart.v
```

This is a compilation check only. UART frame timing and bit order still need testbench simulation and waveform verification.
